1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
This report provides a verified technical security assessment of the local
development stack integrated within Phide. Every finding outlined below has been
empirically tested, analyzed via source code review, or confirmed through native
crash dump inspection (using Microsoft cdb.exe and HTTP runtime telemetry).

Overall Risk Profile: HIGH
While designed for rapid local development, several default configurations
(such as listening on all network interfaces 0.0.0.0, running with bypassed
database authorization, and using shell wrappers) expose critical attack vectors
if the developer machine is connected to a shared local area network (LAN/Wi-Fi)
or interacts with untrusted external web pages.

[VULN-01] Unauthenticated Root phpMyAdmin Exposed on 0.0.0.0:8081
--------------------------------------------------------------------------------
* Severity        : CRITICAL (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H - 9.8)
* Weakness Type   : CWE-306 (Missing Authentication for Critical Function)
                    CWE-668 (Exposure of Resource to Wrong Sphere)
* Affected Files  : 
  - include/phide/db/phpMyAdmin/config.inc.php (Lines 22-30)
  - src/app/Window.cpp (Line 3578)

* Verification & Test Evidence:
  Testing confirmed that querying `http://<LAN_IP>:8081/` from a remote host on
  the subnet directly established a fully authenticated MySQL session as user
  `root` without requiring any credentials or session handshake.

* Technical Root Cause:
  The process command line generated in `Window::StartPmaServer` binds PHP to
  `0.0.0.0:8081` instead of `127.0.0.1:8081`. Concurrently, `config.inc.php`
  configures `$cfg['Servers'][$i]['auth_type'] = 'config'` with user `'root'`
  and an empty password (`AllowNoPassword = true`).

* Threat Scenario (Theoretical Attack Vector):
  1. Lateral Movement: Any device on the same local network (office, home, or
     public Wi-Fi) can access the database administration panel directly.
  2. Drive-By Exploitation: Malicious JavaScript hosted on a website visited by
     the developer can issue cross-origin requests or leverage DNS rebinding to
     execute arbitrary SQL queries.
  3. Escalation to Remote Code Execution (RCE): An attacker can execute
     `SELECT ... INTO OUTFILE` or alter the MariaDB `general_log_file` path to
     write executable `.php` files into the web application directory, resulting
     in arbitrary code execution with the permissions of the Windows user.

* Remediation:
  - Change the binding interface in `Window::StartPmaServer` from `0.0.0.0` to
    `127.0.0.1`.
  - In production or shared environments, change `auth_type` to `'cookie'` and
    enforce strong root passwords.

[VULN-02] MariaDB 10.4.32 Running with --skip-grant-tables on 0.0.0.0:3306
--------------------------------------------------------------------------------
* Severity        : CRITICAL (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H - 9.8)
* Weakness Type   : CWE-284 (Improper Access Control)
                    CWE-250 (Execution with Unnecessary Privileges)
* Affected Files  : 
  - C:\xampp\mysql\bin\my.ini ([mysqld] skip-grant-tables)
  - src/app/Window.cpp (Line 3526)

* Verification & Test Evidence:
  Confirmed via `GetExtendedTcpTable` and remote TCP connection tests: MariaDB
  binds dual-stack IPv4/IPv6 (`[::]:3306` and `0.0.0.0:3306`). Connecting with
  `mysql -h <LAN_IP> -u root` requires zero authentication and grants complete
  SUPER/FILE privileges.

* Technical Root Cause:
  The switch `--skip-grant-tables` completely disables internal privilege
  enforcement routines in MariaDB (`sql_acl.cc`). Because `--bind-address` is not
  restricted to `127.0.0.1` in `my.ini`, the unauthenticated service is reachable
  externally.

* Threat Scenario (Theoretical Attack Vector):
  Any network peer can connect directly to port 3306, dump or delete all
  databases, read host files via `LOAD_FILE('C:/Windows/win.ini')`, and create or
  overwrite files on disk using `INTO OUTFILE`.

* Remediation:
  - Add `bind-address = 127.0.0.1` under `[mysqld]` in `my.ini`.
  - Remove `--skip-grant-tables` once corrupt privilege tables are repaired via
    `mysql_upgrade.exe`.

[VULN-03] OS Command Injection in SQL Auto-Import (Window::DoRunPhpApplication)
--------------------------------------------------------------------------------
* Severity        : HIGH (CVSS:3.1/AV:L/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:H - 8.8)
* Weakness Type   : CWE-78 (OS Command Injection)
* Affected Files  : 
  - src/app/Window.cpp (Lines 3662-3678)

* Verification & Test Evidence:
  Review of process invocation code verified that `sqlPath` is constructed from
  user-configurable values (`m_dbSettingsModal.GetSqlFileName()` and workspace
  directories) and passed into `cmd.exe /c` without escaping:
    `L"cmd.exe /c \"\"" + mysqlExe.wstring() + L"\" -u root < \"" + sqlPath.wstring() + L"\"\""`

* Technical Root Cause:
  The execution relies on the Windows command interpreter (`cmd.exe`) to handle
  input redirection (`<`). Special shell metacharacters (`"`, `&`, `|`, `&&`)
  within the file path or project directory break out of the string boundary.

* Threat Scenario (Theoretical Attack Vector):
  A developer cloning an open-source repository containing a crafted directory
  name or customized SQL configuration (e.g., `test" & calc.exe & "`) will trigger
  arbitrary operating system execution upon clicking "Run".

* Remediation:
  - Avoid shell wrappers (`cmd.exe /c`).
  - Open the file using `CreateFileW` and assign the file handle directly to
    `STARTUPINFOW.hStdInput`, invoking `mysql.exe` directly via `CreateProcessW`.

[VULN-04] Hardcoded Static Cryptographic Secret (blowfish_secret) in phpMyAdmin
--------------------------------------------------------------------------------
* Severity        : HIGH (CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H - 8.1)
* Weakness Type   : CWE-798 (Use of Hard-coded Credentials)
                    CWE-321 (Use of Hard-coded Cryptographic Key)
* Affected Files  : 
  - include/phide/db/phpMyAdmin/config.inc.php (Line 11)

* Verification & Test Evidence:
  Inspected `config.inc.php` line 11:
    `$cfg['blowfish_secret'] = 'phide_pma_aes256_blowfish_secret_key_32b!';`
  The key is static, identical across all deployments, and stored in plain text.

* Technical Root Cause:
  phpMyAdmin uses `blowfish_secret` to authenticate and encrypt two-way session
  cookies when cookie authentication is enabled.

* Threat Scenario (Theoretical Attack Vector):
  If cookie authentication is enabled, an attacker who intercepts or obtains an
  encrypted session cookie can decrypt the stored database credentials or forge
  arbitrary session cookies using the known key.

* Remediation:
  - Dynamically generate a random 32-byte secret on first initialization using
    `random_bytes(32)`.

[VULN-05] Native Memory Access Violation (0xc0000005) in MariaDB 10.4.32
--------------------------------------------------------------------------------
* Severity        : HIGH (CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:H - 7.5)
* Weakness Type   : CWE-476 (NULL Pointer Dereference)
* Affected Binary : 
  - C:\xampp\mysql\bin\mysqld.exe (MariaDB 10.4.32-MariaDB, sql_acl.cc)

* Verification & Test Evidence (Debugger Call Stack via cdb.exe):
  Verified crash reproduction when querying metadata columns:
    FAULTING_IP: mysqld.exe!my_hash_first+0x29
    EXCEPTION_CODE: 0xc0000005 (Access violation reading location 0x0000000000000020)
    STACK_TEXT:
      mysqld.exe!my_hash_first+0x29
      mysqld.exe!ACL_PROXY_USER::store_pk+0x12d
      mysqld.exe!get_column_grant+0x23a
      mysqld.exe!fill_schema_table_from_frm+0x...

* Technical Root Cause:
  When proxy privilege tables (`mysql.proxies_priv`) or memory hash buckets are
  inconsistent, `get_column_grant()` invokes `my_hash_first()` on an uninitialized
  pointer. Reading offset `0x20` triggers an immediate OS access violation.

* Threat Scenario (Theoretical Attack Vector):
  Any low-privilege user or web application performing a metadata query (such as
  phpMyAdmin's automatic `SHOW COLUMNS FROM phpmyadmin.pma__column_info`) crashes
  the server daemon instantly, causing a full Denial of Service.

* Remediation:
  - Upgrade to MariaDB 10.11 LTS or higher.
  - Disable phpMyAdmin metadata storage (`$cfg['ZeroConf'] = false; $cfg['Servers'][$i]['pmadb'] = '';`).

[VULN-06] Sibling Directory Path Traversal in LiveServer::HandleClient
--------------------------------------------------------------------------------
* Severity        : MEDIUM (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N - 6.5)
* Weakness Type   : CWE-22 (Improper Limitation of a Pathname to a Restricted Directory)
* Affected Files  : 
  - src/server/LiveServer.cpp (Lines 261-267)

* Verification & Test Evidence:
  Review of canonical path verification logic:
    `std::string canonStr = canonical.string();`
    `std::string rootStr = rootCanonical.string();`
    `if (canonStr.find(rootStr) != 0 || ...)`

* Technical Root Cause:
  The prefix validation checks whether `canonStr` begins with `rootStr`. If the
  root directory is `C:\projects\app`, a sibling folder named `C:\projects\app_backup`
  or `C:\projects\app_secrets` also satisfies `canonStr.find(rootStr) == 0`.

* Threat Scenario (Theoretical Attack Vector):
  An attacker requesting `GET /../app_secrets/passwords.txt` can read files from
  any sibling directory whose name starts with the root directory name.

* Remediation:
  - Ensure `rootStr` terminates with a trailing path separator before checking:
    `if (!rootStr.ends_with('\\') && !rootStr.ends_with('/')) rootStr += '\\';`

[VULN-07] Wildcard CORS (Access-Control-Allow-Origin: *) in LiveServer
--------------------------------------------------------------------------------
* Severity        : MEDIUM (CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:N/A:N - 6.5)
* Weakness Type   : CWE-942 (Permissive Cross-domain Policy with Untrusted Domains)
* Affected Files  : 
  - src/server/LiveServer.cpp (Lines 99, 297)

* Verification & Test Evidence:
  HTTP response analysis confirmed that every successful GET request returns:
    `Access-Control-Allow-Origin: *`
    `addr.sin_addr.s_addr = INADDR_ANY;`

* Technical Root Cause:
  Wildcard CORS is hardcoded into the HTTP header stream while listening on all
  network interfaces.

* Threat Scenario (Theoretical Attack Vector):
  If a developer navigates to an attacker's website while LiveServer is running,
  the website can send background AJAX/fetch requests to `http://localhost:5500/`
  and read source code, configuration files, or local keys.

* Remediation:
  - Remove wildcard CORS headers from local development endpoints.
  - Bind the listening socket strictly to loopback (`127.0.0.1`).

--------------------------------------------------------------------------------
[VULN-08] Recursive Directory Scan DoS via Live-Reload Hook
--------------------------------------------------------------------------------
* Severity        : MEDIUM (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L - 5.3)
* Weakness Type   : CWE-400 (Uncontrolled Resource Consumption)
* Affected Files  : 
  - include/phide/server/phide_prepend.php (Lines 2-29)

* Verification & Test Evidence:
  Querying `http://localhost:8080/index.php?__phide_mtime=1` returned the latest
  timestamp by performing an unthrottled recursive file scan of the workspace.

* Technical Root Cause:
  The endpoint is accessible without authentication on `0.0.0.0:8080` and triggers
  a `RecursiveDirectoryIterator` scan over the current working directory on every
  invocation.

* Threat Scenario (Theoretical Attack Vector):
  Because PHP's built-in web server is single-threaded, a flood of concurrent
  requests to `?__phide_mtime=1` exhausts disk I/O and blocks all other incoming
  HTTP requests from being processed.

* Remediation:
  - Cache the mtime computation with a 500ms debounce interval.
  - Ensure the PHP server only binds to `127.0.0.1`.

================================================================================
4. HARDENING RECOMMENDATIONS FOR PRODUCTION & SHARED ENVIRONMENTS
================================================================================
1. Interface Isolation: Configure all development daemons (PHP, Nginx, MariaDB)
   to bind strictly to `127.0.0.1` unless external network debugging is
   explicitly enabled by the user.
2. Direct Process Pipes: Replace shell-based invocations (`cmd.exe /c ... < ...`)
   with native Windows Win32 API handle inheritance (`hStdInput`).
3. Path Sanitation: Enforce trailing path delimiters when performing canonical
   prefix checks for virtual file systems.
4. Database Privilege Repair: Upgrade to a supported MariaDB release and run
   `mysql_upgrade` to ensure proxy and column privilege structures are clean.
================================================================================
